## ASSAY-S3-001

**Bucket readable by the public through ACL or policy**

- Resource type: `aws.s3.bucket`
- Base severity: high
- Rationale: An ACL grant to AllUsers or AuthenticatedUsers, or a bucket policy open to any principal, lets anyone on the internet read or change objects.
- Impact: Object data can be listed and downloaded by anyone, which is the most common cloud data leak.
- Remediation: Remove public ACL grants and wildcard policy statements, then turn on Block Public Access.
- Informed by: cis-aws-foundations, cra, iec-62443-4-1, iso-27001, nis2, nist-800-53, nist-csf, soc2
- Reference: <https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-control-block-public-access.html>

## ASSAY-S3-002

**Bucket Block Public Access not fully on**

- Resource type: `aws.s3.bucket`
- Base severity: medium
- Rationale: Block Public Access is the guard rail that stops a later ACL or policy edit from exposing data.
- Impact: A single mistaken grant or policy change would make the bucket public.
- Remediation: Turn on all four Block Public Access settings on the bucket and at account level.
- Informed by: cis-aws-foundations, cra, iec-62443-4-1, iso-27001, nis2, nist-800-53, nist-csf, soc2
- Reference: <https://docs.aws.amazon.com/AmazonS3/latest/userguide/access-control-block-public-access.html>

## ASSAY-S3-003

**Bucket has no default encryption configuration**

- Resource type: `aws.s3.bucket`
- Base severity: medium
- Rationale: Without a default encryption configuration the bucket relies on each writer to request it.
- Impact: Objects may be stored without the key controls and audit trail a KMS key gives.
- Remediation: Set default encryption to SSE-KMS with a customer managed key, or at least SSE-S3.
- Informed by: cra, iec-62443-4-1, iso-27001, nis2, nist-800-53, nist-csf, soc2
- Reference: <https://docs.aws.amazon.com/AmazonS3/latest/userguide/default-bucket-encryption.html>

## ASSAY-S3-004

**Bucket versioning not enabled**

- Resource type: `aws.s3.bucket`
- Base severity: low
- Rationale: Versioning keeps earlier object versions so a delete or overwrite can be undone.
- Impact: Ransomware, a bad deploy or an accidental delete destroys data with no way back.
- Remediation: Enable versioning and add a lifecycle rule to expire old versions.
- Informed by: cis-aws-foundations, cra, iec-62443-4-1, iso-27001, nis2, nist-800-53, nist-csf, soc2
- Reference: <https://docs.aws.amazon.com/AmazonS3/latest/userguide/Versioning.html>

## ASSAY-S3-005

**Bucket access logging not enabled**

- Resource type: `aws.s3.bucket`
- Base severity: low
- Rationale: Server access logs are the record of who read or wrote objects.
- Impact: After a leak there is no evidence of what was accessed or by whom.
- Remediation: Enable server access logging to a separate log bucket, or CloudTrail data events.
- Informed by: cis-aws-foundations, cra, iec-62443-4-1, iso-27001, nis2, nist-800-53, nist-csf, soc2
- Reference: <https://docs.aws.amazon.com/AmazonS3/latest/userguide/ServerLogs.html>

## ASSAY-EC2-001

**SSH open to the internet**

- Resource type: `aws.ec2.security_group`
- Base severity: high
- Rationale: SSH from anywhere invites constant password and key guessing against every attached host.
- Impact: A weak key, leaked key or SSH bug becomes a direct shell on the host.
- Remediation: Limit port 22 to known admin ranges or remove it and use Session Manager.
- Informed by: cis-aws-foundations, cra, iec-62443-4-1, iso-27001, nis2, nist-800-53, nist-csf, soc2
- Reference: <https://docs.aws.amazon.com/vpc/latest/userguide/security-group-rules.html>

## ASSAY-EC2-002

**RDP open to the internet**

- Informed by: cis-aws-foundations, cra, iec-62443-4-1, iso-27001, nis2, nist-800-53, nist-csf, soc2

## ASSAY-EC2-005

**EBS volume not encrypted**

## ASSAY-IAM-001

**Policy allows every action on every resource**

- Resource type: `aws.iam.policy`
- Base severity: critical
- Rationale: Action * on Resource * (or Allow with NotAction) hands out every permission in the account.
- Impact: Anyone holding the policy can read all data, create users and turn off logging.
- Remediation: Replace the statement with the specific actions and resources the workload needs.
- Informed by: cis-aws-foundations, cra, iec-62443-4-1, iso-27001, nis2, nist-800-53, nist-csf, soc2

## ASSAY-IAM-003

## ASSAY-IAM-004

## ASSAY-IAM-005

**Active access key older than 90 days**

- Resource type: `aws.iam.user`
- Base severity: medium
- Rationale: Long lived keys end up in scripts, laptops and repos; age raises the odds one has leaked.
- Impact: A leaked key works from anywhere until it is rotated.
- Remediation: Rotate the key, delete the old one and move workloads to roles with temporary credentials.
- Informed by: cis-aws-foundations, cra, iec-62443-4-1, iso-27001, nis2, nist-800-53, nist-csf, soc2

## ASSAY-IAM-007

- Rationale: Root keys cannot be limited by any policy and are rarely needed.
- Impact: A leaked root key is a full and unrestricted takeover of the account.
- Remediation: Delete root access keys and use IAM roles for all programmatic work.
- Informed by: cis-aws-foundations, cra, iec-62443-4-1, iso-27001, nis2, nist-800-53, nist-csf, soc2

## ASSAY-ACM-002
